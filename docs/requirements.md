# Requirements

Идентификаторы стабильны. Реализация этапа N закрывает только REQ этого этапа. Не закрывать «заодно» чужой этап.

Платформа: Windows 10 (x64) и Windows 11 (x64), .NET 8, UI WPF, язык интерфейса русский. IPv4. Облака нет.

## Глоссарий

- **Класс** — сессия на ПК учителя: PIN, TCP-хаб, список учеников.
- **Агент** — процесс ученика.
- **Сессия ученика** — связь этого агента с текущим классом (`student_id` + `session_token`).
- **Fail-open** — запреты сняты, захват выключен, ПК обычный.
- **Надзор** — учитель получает кадры экрана выбранного ученика.

## Функциональные

### Этап 1 — связь (делать первым)

| ID | Требование | Принятие |
|---|---|---|
| FR-01 | Учитель создаёт класс: отображаемое имя (по умолчанию «Класс»), PIN из 6 символов (ровно 3 латинские буквы и 3 цифры, вперемешку), слушает UDP `47820` и TCP `47821` | PIN крупно виден в UI учителя |
| FR-02 | Ученик в LAN находит класс по UDP без PIN в эфире | В списке учителя появляется ученик после Join |
| FR-03 | Join по TCP: PIN, имя, hostname, версия. Успех → `student_id` + `session_token`. Неверный PIN → отказ с текстом, процесс не падает | Неверный PIN не пускает, верный пускает |
| FR-04 | Heartbeat только по уже открытому TCP класса. Любое входящее сообщение обновляет `lastRecv`. Нет пинга интернета, нет облака | Выключение внешнего интернета при живой LAN не рвёт класс и не закрывает exe |
| FR-05 | Нет данных ≥10 с → пауза стрима (на этапе 1 стрима ещё нет — состояние «stale» всё равно считается). Приложение не завершается | Оба процесса живы |
| FR-06 | Нет данных ≥120 с → fail-open, статус `Ended` | Запреты (когда появятся) сняты; на этапе 1 — агент в ожидании без сессии |
| FR-07 | TCP оборвался раньше 120 с → статус `Reconnecting`, exe живы, повторный Join с тем же token+PIN, поиск UDP если IP сменился | Моргнувший Wi‑Fi склеивает сессию без перезапуска приложений |
| FR-08 | Явный `session_end` (кнопка, закрытие Teacher) → fail-open сразу, не ждать 120 с | Плашка надзора сразу в «ожидание класса» |
| FR-09 | UI ученика: плашка + трей. Тексты по статусу — см. `ui.md` | Текст соответствует статусу |
| FR-10 | После Join крестик сворачивает плашку в трей (сессия жива). Отключение от урока и выход из процесса — через трей с подтверждением, без PIN. Kill из диспетчера допускается | Крестик не рвёт урок; выход — явное подтверждение; kill — процесс мёртв |
| FR-11 | UI учителя: слева список (имя, статус: онлайн / переподключение / нет) | Статусы меняются по FR-05…08 |
| FR-12 | После `session_end` агент не обязан выходить: ждёт новый класс. Автозапуска после reboot нет | Reboot ученика → агента нет, пока не запустят руками |
| FR-13 | Хаб рассчитан на много TCP-клиентов. Этап 1 можно принять на 1:1 и на loopback | Два Student к одному Teacher на одной машине — допустимый техтест |

### Этап 2 — смотреть (не начинать до приёмки этапа 1)

| ID | Требование | Принятие |
|---|---|---|
| FR-20 | Выбран ровно один ученик → `stream_start` только ему, предыдущему `stream_stop` | В сети один поток JPEG |
| FR-21 | DXGI → JPEG, ориентир 8–12 fps, длинная сторона ≤1280, только пока Online и не stale | На учителе виден рабочий стол ученика |
| FR-22 | Краткий список процессов выбранного: процессы с главным окном + активный exe, период ~2–3 с | Список читаемый, ключ — имя exe |
| FR-23 | Смена ученика переключает стрим и список процессов | Старый поток останавливается |

### Этап 3 — запуск и запрет (не начинать до приёмки этапа 2)

| ID | Требование | Принятие |
|---|---|---|
| FR-30 | Пресет у учителя (локальный JSON). Добавление из `installed_hints` ученика = утверждение учителем | Без диалога у ученика |
| FR-31 | `launch_app` — разовый старт. Не хук | У ученика открылось приложение |
| FR-32 | `set_block_list` — имена exe, OrdinalIgnoreCase, только имя файла. Вотчер в RAM: нашёл — закрыл | Запрещённое закрывается и не держится |
| FR-33 | Не убивать собственные процессы (`Teacher`, `Student`, имена начинающиеся с `NordControl`) | Агент не совершает самоубийство |
| FR-34 | Fail-open снимает блоклист: `session_end`, `Ended`, смерть процесса, reboot без автозапуска | После отключения учителя запрещённое снова запускается |

## Нефункциональные

| ID | Требование |
|---|---|
| NFR-01 | LAN only. Запрещены: HTTP(S) к интернету как часть продукта, облачный signaling, «проверка интернета» как условие работы |
| NFR-02 | Политики только в RAM процесса агента |
| NFR-03 | Надзор видимый. Нет маскировки процесса, кейлоггера, записи экрана на диск |
| NFR-04 | `NordControl.Protocol` без Win32-типов |
| NFR-05 | Логи только локально (`%LocalAppData%\NordControl\logs`), без телеметрии |
| NFR-06 | Первый прогон: два exe без установщика. Публикация self-contained `win-x64` для ПК без SDK |
| NFR-07 | Учителю нужен inbound TCP/UDP. Ученику inbound не нужен |
| NFR-08 | PIN разделяет кабинеты в LAN, это не криптография. TLS в ядре нет |
| NFR-09 | Пока этапы 1–3 не приняты на железе — нет чата, лока экрана, магазина, лицензий, Android UI, автозапуска-службы |

## Вне скоупа v1

Удалённый ввод мыши/клавиатуры, запись урока, фильтр сайтов, микрофон, камера, Store, онлайн-лицензия, IPv6 как основной путь, macOS/Linux.

## Сценарии приёмки (этап 1)

1. **Loopback.** На одном ПК Teacher + Student. Join по PIN. В списке ученик «онлайн».
2. **Неверный PIN.** Ученик не в списке, оба окна живы.
3. **Закрыть Teacher.** Student сразу «ожидание класса», не висит 120 с в reconnect.
4. **Убить Teacher в диспетчере.** Student в переподключении, к ~120 с — ожидание. Student.exe сам не закрылся.
5. **Выключить интернет (шлюз), LAN оставить.** Сессия жива.
6. **Закрыть Student крестиком после Join.** Процесс жив, плашка в трее, сессия не рвётся.
7. **Две машины.** Ноут Teacher, ПК Student, одна LAN. Discovery + Join. Повторить 3 и 5.
