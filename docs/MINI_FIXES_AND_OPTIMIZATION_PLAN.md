# План оптимизации, устранения дублирования и аудита боевого режима (Nord Control)

> **Цель документа:** Систематизировать доработки по поверхностной оптимизации, устранению дублирования, тестированию в условиях реальной сети (боевой режим), проверке отказоустойчивости и минимизации нагрузки на CPU / RAM / Сеть.

---

## 1. Поверхностная оптимизация кода и устранение дублирования

### 1.1. Унификация и дедупликация логики
- [ ] **Нормализация имен исполняемых файлов (`NormalizeExeName`):**
  - **Проблема:** Логика очистки пути (`Path.GetFileName`) и добавления суффикса `.exe` дублируется в `RamAppBlocker`, `ProcessMonitor`, `InstalledAppsScanner` и `TeacherPreset`.
  - **Решение:** Вынести единый статический метод-хэлпер `ProcessNameHelper.Normalize(string rawName)` в `NordControl.Core.Helpers` с гарантированным регистронезависимым сравнением.
- [ ] **Единый пул буферов для передачи кадров (`ArrayPool<byte>`):**
  - **Проблема:** При захвате 8–12 кадров/сек регулярное выделение новых массивов `byte[]` для JPEG приводит к фрагментации кучи больших объектов (LOH) и частым сборкам мусора (GC Gen2).
  - **Решение:** Использовать `ArrayPool<byte>.Shared` или многоразовые `MemoryStream` при сжатии и отправке кадров в `DxgiScreenCapturer` и `GdiScreenCapturer`.
- [ ] **Оптимизация десериализации JSON:**
  - **Проблема:** Передача `WireMessage` в цикле сокета.
  - **Решение:** Проверить переиспользование кэшированных экземпляров `JsonSerializerOptions` во всех проектах.

### 1.2. Гармонизация жизненного цикла (`IDisposable` / `IAsyncDisposable`)
- [ ] **Упорядочивание освобождения сокетов и CancellationTokenSource:**
  - Гарантировать корректный порядок закрытия: `cts.Cancel()` $\rightarrow$ `stream.Close()` $\rightarrow$ `client.Close()` $\rightarrow$ `cts.Dispose()` во всех фоновых циклах без выброса необработанных `ObjectDisposedException`.

## 2. Аудит боевого режима (Field-Testing) и план фиксов (Edge Cases)

### 2.1. Сетевые сценарии и отказоустойчивость LAN
- [ ] **Смена сетевого интерфейса / IP (Wi-Fi $\leftrightarrow$ Ethernet, переподключение роутера):**
  - **Сценарий:** Ноутбук переключился с Wi-Fi 2.4 GHz на 5 GHz или сменил IP по DHCP во время урока.
  - **Ожидаемое поведение:** `ClassClient` в течение 2–3 секунд переходит в `Reconnecting`, заново рассылает UDP-пробы и склеивает сессию по `session_token` без участия пользователя.
  - **Фикс:** Подписка на событие `NetworkChange.NetworkAddressChanged` для превентивного сброса кэша адресов.
- [ ] **Изоляция клиентов на Wi-Fi роутере (AP Isolation):**
  - **Сценарий:** В школьной сети роутер блокирует широковещательный UDP broadcast.
  - **Решение:** Проверить, что ручной ввод IP учителя в клиенте (`manualTeacherIp`) безупречно отрабатывает прямой TCP-коннект в обход UDP discovery.
- [ ] **Режим сна / закрытие крышки ноутбука ученика (Suspend / Resume):**
  - **Сценарий:** Ученик закрыл крышку ноутбука на 30 секунд.
  - **Ожидаемое поведение:** При выходе из сна сокет рвется $\rightarrow$ статус `Reconnecting` $\rightarrow$ успешный повторный Join без падения приложения.

### 2.2. Защита UI Учителя от подтормаживаний (UI Thread Smoothness)
- [ ] **Асинхронное декодирование JPEG на стороне Учителя:**
  - **Проблема:** Создание `BitmapImage` на UI-потоке из `byte[]` с высоким разрешением (1080p/720p) может вызывать микрофризы интерфейса.
  - **Решение:** Декодировать JPEG в фоновом потоке, вызывать `.Freeze()` для `BitmapSource`, и только затем передавать готовый объект в `Image.Source` через Dispatcher.

### 2.3. DPI-масштабирование и многомониторные системы
- [ ] **Проверка масштабирования Windows (125%, 150%, 175%):**
  - Убедиться, что `DxgiScreenCapturer` и `GdiScreenCapturer` захватывают полный физический рабочий стол, а не обрезанный угол из-за DPI-виртуализации Windows.
  - Указать `<application xmlns="urn:schemas-microsoft-com:asm.v3"><windowsSettings><dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness></windowsSettings></application>` в манифестах приложений.

## 3. Профилирование и оптимизация ресурсов (CPU / RAM / Сеть)

### 3.1. Нормативы нагрузки на ПК Ученика (Student)

| Режим работы | Максимальный CPU (Core i3 / Ryzen 3) | Максимальный RAM | Сетевой трафик |
|---|---|---|---|
| **Покой (Idle / Ожидание класса)** | **< 0.1%** | **< 35 MB** | 0 Кбит/с |
| **Урок без стрима (Teacher смотрит другого)** | **< 0.5%** | **< 45 MB** | < 5 Кбит/с (только heartbeat + процесс-лист раз в 2.5 с) |
| **Активный стрим экрана (8–12 FPS)** | **< 2.5%** | **< 60 MB** | 1.5 – 3.0 Мбит/с |

- [ ] **Оптимизация мониторинга процессов `ProcessMonitor`:**
  - `Process.GetProcesses()` вызывается раз в 2.5 секунды. Исключить повторные аллокации тяжелых модулей (`MainModule`), кэшировать имена системных процессов.
- [ ] **Оптимизация `RamAppBlocker` (интервал 500 мс):**
  - Быстрая фильтрация по PID / исключение уже проверенных безопасных системных процессов.
  - Нулевая нагрузка на CPU при пустом блоклисте.
